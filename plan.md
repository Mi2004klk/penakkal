## 0. CONTEXT — WHAT CHANGED SINCE THE LAST AUDIT
 
Since the v3.0 audit, a partial upgrade landed. **Fixed:** taxonomy exists in data (category/categoryTamil/tags/authorSlug/coverBlur populated), articles split into `articles-meta.json` + `articles-content/*.json`, `public/search-manifest.json` is generated by `npm run build`, shared `PageShell`/`LoadingSpinner`/`ReadingTime`/`HighlightText`/`lib/constants.ts` primitives exist, FilterPanel got a real focus trap + dialog semantics, breadcrumbs scroll instead of clipping, and the old `cleanUrls` conflict is gone.
 
**But the upgrade introduced critical regressions and left large gaps.** The worst: the Tailwind v4 `@theme` now defines `--spacing-8: 8px … --spacing-104: 104px`, which **overrides Tailwind's numeric spacing utilities — verified in compiled CSS, `.pt-16` renders 16px instead of 64px, `.gap-8` renders 8px instead of 32px** — so every overridden spacing step on the site renders at ~25% of its intended size, including the fixed-header offset. Separately, the meta/content split corrupted 267 `author` fields with full article text (worst: 316,244 characters, rendered unclamped in cards), and the design-token layer has a font-size/color namespace collision, three undefined font tokens, and light-mode-invisible zone surfaces.
 
This plan: (1) catalogs **every** verified finding with severity, priority, expected improvement, and exact implementation approach; (2) sequences a 10-phase roadmap covering design system, component standardisation, responsive, usability, performance/assets, accessibility, SEO, animations, and production QA.

## 1. HOW TO READ THIS PLAN
 
- **Severity** — impact if unfixed: **C**ritical (broken/blank/dangerous), **H**igh (majorly degrades UX/a11y/perf), **M**edium (inconsistency, polish, edge case), **L**ow (nit).
- **Priority** — when to fix: **P0** = now (regression or user-facing breakage), **P1** = current cycle, **P2** = next cycle, **P3** = opportunistic polish.
- Each finding: `ID · Severity/Priority · Location · Problem → Expected improvement · Implementation approach`.
- Roadmap phases reference finding IDs. Acceptance criteria are per-phase.
 
## 2. GUARDRAILS (binding constraints)
 
1. **No redesign of working flows.** Navigation model, bookmark/history/search behavior, view modes, filter semantics, article layout concept, and all `lib/` business logic (recommendations, hijri, article queries) stay as-is unless a finding explicitly requires a behavior-preserving refactor.
2. **Business logic is preserved verbatim** where touched: `recommendations.ts` scoring, `useStore.ts` persist schema (v2) with a v3 migration only if needed, `articles.ts` query semantics.
3. Every phase ships behind visual review at 320/375/768/1024/1440 in light + dark; no phase ends with new console errors or hydration warnings.
4. Data-pipeline changes are **additive transforms** over `source-data/` — never hand-edit generated artifacts; all fixes go into `scripts/*.mjs` so reruns are idempotent.
5. Existing routes/URLs must not change (trailing-slash style preserved); SEO phase only *aligns* signals, never restructures paths.
6. Anything ambiguous is verified against the compiled build (`out/`) or DataLayer before coding — this audit already caught two "documented" states that no longer matched reality.

# PART I — FINDINGS BY DOMAIN
 
## 3. DESIGN SYSTEM FOUNDATION (DS)
 
### DS-1 · C/P0 — Tailwind spacing scale is corrupted by `@theme` overrides
- **Location:** `src/app/globals.css:85-92`; verified in compiled `out/_next/static/chunks/*.css`: `.pt-16{padding-top:var(--spacing-16)}` → 16px, `.gap-8{gap:var(--spacing-8)}` → 8px.
- **Problem:** In Tailwind v4, `--spacing-*` theme keys **replace** the default `calc(var(--spacing) × N)` utilities. Every overridden step (`8,16,24,32,40,48,64,104`) now renders at its px-number instead of 4px×N: `p-8`=8px (want 32), `py-16`=16px (want 64), `mb-24`=24px (want 96). The scale is non-monotonic (`gap-8`=8px < `gap-6`=24px). Worst concrete effect: every page shell's `pt-16` header clearance is 16px while `--header-height` is 64px — content hides under the fixed header.
- **Expected improvement:** The entire spacing system returns to the standard scale; page rhythm, header clearance, card padding, and section gaps render as authored everywhere.
- **Implementation:** Delete lines 85-92 entirely. If DESIGN.md's px-named scale is still wanted as *documentation*, keep it in DESIGN.md only — or rename to non-colliding custom properties (`--space-section: 64px`) consumed explicitly. Then audit the rendered result: because dozens of components were visually tuned **against the broken scale** (or mix overridden and non-overridden steps like `py-12`=48px vs `py-16`=16px), run each page at the breakpoints and normalize spacing to the corrected values (this doubles as the Phase-3 spacing pass). Add a CI guard: a tiny script that builds and asserts `.pt-16` compiles to `calc(var(--spacing)*16)`, failing on any future `--spacing-N` reintroduction.
 
### DS-2 · C/P0 — `text-heading` namespace collision (font-size vs color)
- **Location:** `src/app/globals.css:38` (`--color-heading`) and `:58` (`--text-heading: clamp(24px,4vw,30px)`).
- **Problem:** Both variables emit a `.text-heading` utility; only one survives in compiled CSS (color). All 67 `text-heading` usages set color only; places relying on it for size (e.g., `FilterPanel.tsx:126` h3) silently fall back to 16px.
- **Expected improvement:** One unambiguous token per role; heading sizes actually apply.
- **Implementation:** Rename the color to `--color-heading-text` → `text-heading-text` (or drop it — it duplicates `--color-heading`'s intent of near-black; simpler: keep color name, rename the **size** token to `--text-heading-md`). Sweep all 67 usages: those meaning color → keep `text-heading`; those meaning size → new name. Verify compiled CSS emits both utilities.
 
### DS-3 · C/P0 — Three font tokens referenced but never defined; cyclic definitions
- **Location:** `--font-tamil` (`globals.css:140,351`; `page.tsx:78`), `--font-quran` (`globals.css:143,467,503`), `--font-condensed` (`globals.css:307`) — none defined. Also `globals.css:47-50` define `--font-display: var(--font-display), …` — self-referential (cycle) at `:root`.
- **Problem:** `.prose` font-family, `.quran-verse`, `.prose-article .arabic-text`, `.section-eyebrow`, and the home hero excerpt all resolve to invalid-at-computed-value → silent inheritance. 3,887 inline Arabic Quran/hadith spans in article bodies do **not** use the loaded Noto Naskh Arabic while component Arabic does → two different Arabic typefaces on the same page.
- **Expected improvement:** Every font-family declaration resolves; article Quran text renders in the loaded Arabic face; hero and eyebrows use their intended faces.
- **Implementation:** In `@theme`, define the four *families* cleanly with distinct internal variable names — `--font-display`, `--font-body`, `--font-ui`, `--font-arabic` — where the theme key maps to `var(--next-font-display), 'Tamil Sangam MN', 'Latha', serif` etc. (rename the next/font CSS variables at `layout.tsx:9-28` to `--next-font-*` to break the cycle). Alias `--font-tamil: var(--font-body)`, `--font-quran: var(--font-arabic)`, and delete `--font-condensed` (Barlow was removed from the font payload — the eyebrow should use `--font-ui` bold per DESIGN.md mapping). Sweep the 116 `font-[family-name:var(--font-<name>)]` arbitrary classes to the existing `font-ui`/`font-body`/`font-display` utilities (largest single cleanup: 35 files).
 
### DS-4 · C/P0 — `.zone-forest` / `.zone-cream` have no light-mode background
- **Location:** `globals.css:244-260` consume `--color-surface-forest-stage` / `--color-surface-cream-paper`, defined only inside `.dark` (`:216-217`).
- **Problem:** In light mode both zones are transparent; `.zone-forest` puts **white text on transparent** — readable today only because pages coincidentally paint `bg-forest-stage` underneath (home hero) or match `--color-surface-page` (cream). Any layout shift breaks it; it is semantically inverted.
- **Expected improvement:** Zones render their intended background in both themes by construction.
- **Implementation:** Move `--color-surface-forest-stage` and `--color-surface-cream-paper` into `@theme` with light values (forest `#0d542b` is theme-invariant; cream-paper is the light page color; dark variants override inside `.dark`). Verify Footer, home content, blog shell, article body in both themes.
 
### DS-5 · C/P0 — Shadow tokens broken/undefined
- **Location:** `globals.css:106` `--shadow-card: none` while `shadow-card` is used where lift is expected (`category/page.tsx:43`, `about/page.tsx:14`, `author/[name]/page.tsx:62`, `history/page.tsx:45,65`); `shadow-dropdown` (`TableOfContents.tsx:108`) defined nowhere.
- **Expected improvement:** Card elevation exists; dropdowns have depth.
- **Implementation:** Set `--shadow-card: 0 1px 3px rgba(0,0,0,0.06)`; add `--shadow-dropdown: 0 4px 16px rgba(0,0,0,0.12)`. Audit the off-system shadows (`shadow-sm/md/lg/xl` ×12 uses) and either tokenize or replace with the token set (see DS-9).
 
### DS-6 · H/P1 — Typography scale drift: 4 title systems, 4 eyebrow variants, 4 card-title variants
- **Location:** Page titles: `.editorial-headline` (12 uses) vs hand-rolled `text-4xl md:text-5xl` (`blog/[slug]/page.tsx:100`, `search/page.tsx:168`) vs `text-2xl` empty-states vs `text-8xl md:text-9xl` error digits. Fix Bismillah order (single token).

## 4. CONTENT RENDERING & DATA (CRX)
 
### CRX-1 · C/P0 — `author` field contains full article text; rendered unclamped
- **Location:** Data: 267 articles with author > 60 chars; worst 316,244 chars (id 8040). Rendered raw at `ArticleCard.tsx:68,120` (all listing pages), `page.tsx:83` (hero byline), `blog/[slug]/page.tsx:107`, `AuthorInfoCard.tsx:14-15`, `author/[name]/page.tsx:26,66` (multi-MB `<title>`), `feed.xml/route.ts:31`.
- **Problem:** The meta/content split (or upstream WordPress export) left article body text inside `author`; listing pages explode to thousands of lines; SEO titles/JSON-LD/RSS poisoned.
- **Expected improvement:** Clean author names everywhere; display never trusts data length.
- **Implementation:** (a) **Pipeline fix** in `scripts/process-json.mjs`: author = first line, strip HTML, clamp to a sane max (e.g., 80 chars at a word boundary), and derive `authorSlug`/`authorTamil` from the cleaned value; add `data:validate` assertions (author ≤ 80 chars, no `<`/`>`). (b) **Defense in depth:** a `cleanAuthor()` util in `lib/` + `line-clamp-1` on every byline surface; author pages derive display name from `authorTamil` with fallback. Rebuild meta/content + search manifest.
 
### CRX-2 · C/P0 — Mangled WordPress image markup leaks visible junk text + broken images
- **Location:** 421 occurrences across 172 article bodies (e.g., `articles-content/1327-….json`): `<img src="…_&lt;span dir=" />212217657193692_<span dir="rtl">1809815094771180533</span>_n.jpg" …>` injected at `blog/[slug]/page.tsx:147`.
- **Problem:** Browser parsing of the malformed tag emits (a) a failed image request, (b) **visible stray digits/fragments as body text**, (c) a stray RTL span — corrupting ~25% of the reading surface.
- **Expected improvement:** Clean, valid article HTML; no visible junk.
- **Implementation:** Build-time sanitizer step in `process-json.mjs` (run once over content, idempotent): parse each body with a tolerant parser (`parse5`/`cheerio`), drop text nodes that were attrs of broken tags, normalize the FB-CDN filename pattern, then apply CRX-3 rules. Add a validation count: 0 `<span` inside any attribute value.
 
### CRX-3 · C/P0 — Content images: no alt (98%), no lazy-loading, dead/hotlinked sources
- **Location:** 524 `<img>` in content: 516 empty/missing alt, **0** `loading="lazy"`, 0 srcset. Sources: 212 → `http://penakkal.com/wp-content/…` (legacy host, plain http), ~13 third-party hotlinks (fbcdn/bbc/thesite), and 21 of 40 sampled local `/media/...` paths **missing on disk**.
- **Expected improvement:** All content images local, sized, lazy, attributed; zero broken requests in the article reading flow.
- **Implementation:** Extend `scripts/download-media.mjs`: download WP-hosted images to `public/media/content/…` and rewrite srcs; for genuinely dead sources keep the `</img>`→remove or replace with the default cover pattern (decide per count after run). Sanitizer adds `loading="lazy"`, `decoding="async"`, `alt` = derived from caption/adjacent text else `alt=""` (decorative), and wraps in a `.figure` container with the existing prose styles. Report: remaining external hosts, missing files.
 
### CRX-4 · C/P0 — Build/deploy configuration is internally inconsistent
- **Location:** `next.config.ts` = only `trailingSlash: true` (no `output: 'export'`, no `images.unoptimized`), but `package.json` `postbuild: pagefind --site out` expects an exported `out/`, and a stale `out/` tree exists; `next/image` now requires the optimizer (fine on Vercel, broken under export).
- **Problem:** As committed, `npm run build` + `postbuild` either fail or index a stale tree; the hosting mode (SSR-on-Vercel vs static export) is ambiguous, and image behavior silently changed.
- **Expected improvement:** One declared deployment mode; reproducible build.
- **Implementation:** Decide: **(recommended) Vercel SSR/ISR mode** — remove `postbuild` pagefind step *only if* search no longer needs Pagefind (site already uses `search-manifest.json` for search; confirm Pagefind's role — if redundant, drop it; if wanted, keep `out/`-independent indexing) and keep the image optimizer. Alternative: restore `output:'export'` + `images.unoptimized` + custom loader (Phase-5 image variants). Either way: delete the stale `out/`, make CI run the full pipeline (`data:all && build`), and document the mode in README. Verify all `next/image` usages against the chosen mode.

## 5. UI STATES, FORMS & OVERLAYS (UIX)
 
### UIX-1 · C/P0 — Header stacking context traps every overlay; z-index war
- **Location:** `Header.tsx:116` `fixed … z-[var(--z-header)]` creates a stacking context; SearchModal (`:307`), drawer (`:247`), dropdown (`:169`) render **inside** `<header>`, so their z-values are local. Verified consequences: ReadingProgress `z-[49]` (rendered outside header) paints **over** the open SearchModal; bottom MobileNav `z-40` (later in DOM) paints over the open mobile drawer's bottom 64px.
- **Expected improvement:** Overlay layering is globally correct; no element paints over an open modal/drawer.
- **Implementation:** **Portal overlays out of `<header>`** — render SearchModal/dropdown/drawer via `createPortal(document.body)` (or lift them to `PageShell` level as siblings after the header). Then apply the DS-10 z-ladder. Regression-test: open modal → scroll article (progress bar must be under modal), open drawer → bottom nav must be under drawer backdrop.

## ADDENDUM v4.1 — Round-4 Audit (September 2026): Section-by-Section Re-Audit & Fix Log

A fourth full audit was run section-by-section and component-by-component against the post-v4.0 codebase (three parallel audit passes: all 14 routes, all ~65 components, and system-level tokens/contrast/typography/spacing/icons/assets/perf/SEO). **22 new findings** were identified and **all are now fixed**. The findings clustered into two root causes plus per-surface issues:

### Root cause 1 — Dark-mode token leakage (theme/contrast cluster)
`.dark` remapped the semantic surface/text tokens but never remapped the raw-palette tokens used as text/UI colors. On dark surfaces: `text-true-black` = **1.3:1**, `text-stone` = **1.6–2.7:1**, `--color-surface-alt` stayed light (Sidebar gradient = half-white widget), `text-moss` = **3.4:1**. The entire SearchModal was unreadable in dark mode.
**Fix (token level, not per-call-site):** `.dark` now overrides `--color-stone: #a8a29e`, `--color-ash: #57534e`, `--color-surface-alt: #2a2a2a`; all 73 `text-moss` text usages swept to `text-text-link` (identical in light, lime in dark); remaining `text-true-black`/`text-stone` usages swept to `text-heading`/`text-body-text`/`text-muted-text` (SearchModal, ViewToggle, category index, about, skip link); BismillahBlock gained a `tone` prop (coral fails on forest at 2.46:1 → lime on hero); Button `alert` variant → dark label on coral (3.68:1 → 5.7:1); Avatar dark → lime initial; error/404 headings → `text-error`; all new pairs locked into `scripts/verify-contrast.mjs` (now 27 checks).

### Root cause 2 — z-index utilities never compiled
`--z-nav/progress/dropdown/drawer/modal/toast` are **not** a Tailwind v4 theme namespace — the `z-modal`, `z-nav`… classes used in 10 places never existed in the compiled CSS, leaving portal overlays at z-auto beneath the fixed header.
**Fix:** explicit `@utility z-*` definitions in globals.css. Overlay backdrop now uses the theme-aware `bg-overlay` token (was hardcoded `bg-black/60`, losing the 0.7 dark value).

### Page-level fixes
- **Article page:** nested `<main>` inside PageShell's landmark (invalid HTML) → `div`; **no horizontal gutters at any width below xl** → `px-4 md:px-8` (matches its own loading skeleton); doubled `pb-20` removed; BreadcrumbList JSON-LD now matches the visible 4-level breadcrumb (`/blog` level added); tags eyebrow `h2` → sr-only h2 + aria-hidden p; related-articles heading demoted from display-size clamp to `text-heading-md`; OG gains `modifiedTime`.
- **Home:** nonexistent `.btn-ghost` class (CTA rendered as bare text) → `buttonStyles({variant:'ghost'})`; both containers now respect `--page-max-width` (header/content edges align at 1280–1535px).
- **Category index:** dark-invisible card titles/counts → semantic tokens; raw `text-2xl` → `text-heading-sm`.
- **About:** zero page-top spacing/edge-flush on the hasHero path → `py-12 md:py-20 px-4`; dark text fixes.
- **History:** missing `metadata` + `robots: noindex` on a private page → added (matches /saved).
